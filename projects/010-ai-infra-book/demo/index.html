03 / FROM CONSTRAINTS TO DECISIONS

它的核心方法：先算，再测。

01

描述任务

模型、输入长度、输出长度、并发与质量要求。

02

拆分资源

需要多少计算、存储和数据搬移？哪里存在等待？

03

对照硬件

检查显存容量、带宽、算力和通信约束。

04

实测与修正

用相同条件对照实际执行，查找遗漏和优化空间。

一个具体问题

为什么上下文变长后，
服务变得更吃力？

先看资源：常规注意力模型保存的历史状态（KV 缓存）通常随上下文和批量增长；生成时还需要访问历史信息。

再看机制：缓存结构、注意力方式、前缀复用等会改变占用和读写；不能对所有架构套用同一个比例。

最后看实测：真实延迟还受算子融合、调度和硬件利用率影响。静态估算用于解释和定位，不能直接当作速度测试。

最小上手流程

复算一次 Qwen3-8B 的输入处理

git clone https://github.com/bojieli/ai-infra-book.git
cd ai-infra-book
git checkout b069b6971faf6c4701b57a8b025462b9f2694b8f
python calculations/calc.py models
python calculations/calc.py forward --model qwen3-8b --tokens 8192 --format md

你会得到什么：模型支持状态，以及该输入场景的逐算子资源估算表。它不加载权重生成回答。

如何继续：改变输入长度或批量大小，对照输出差异；先读工具说明中的计算口径和未覆盖项。

下载说明：该版本默认跳过大体积 LFS 文件。正文与静态计算不需要它们；复现实跑实验时按对应目录取用。

05 / VALUE & LIMITS

对我们有什么实际意义？

本项目的分析判断

把它作为 AI 系统分析参考书。

研究开源模型与部署方案时，可用它统一讨论“显存、吞吐、时延、带宽”的语言，并用计算工具检查数量级是否合理。

当前最值得复用的是问题拆解方法、资源计算入口和实验记录方式。当有具体推理服务或硬件瓶颈时，再深入对应章节与实验。

回到学习路线 ↑

如果只是日常调用模型 API

先理解基础和推理优化即可。它不会直接替你搭建应用，也不直接提升提示词质量。

如果要部署或训练模型

这里提供分析与实验参考；实际服务、权重管理和集群运维仍需要相应的执行工具。

如果要做容量或性能承诺

静态结果受假设与覆盖范围限制；必须在目标硬件、模型与负载上实测，再判断可用容量和速度。
