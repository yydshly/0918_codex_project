# 理解、实现方式与产品机会

资料核验：2026-09-18；摘要与理解图修订：2026-09-19。Claude Mods 展示借助插件和 Hook 扩展 Agent 工作过程的机制与示例；对我们的价值是基于这些机制开发自己的产品。本文区分公开资料、原创产品推演、网页验证，动态接口以实际安装版本为准。

## 1. 原始链接在讲什么

[主帖](https://github.com/anthropics/claude-code/issues/91870)介绍 Claude Mods 与 Function Hooks。[用户最初链接的评论](https://github.com/anthropics/claude-code/issues/91870#issuecomment-5666255143)展示 cc-arcade：在 Claude Code 界面内提供小游戏，并用运行事件关联暂停等行为。评论是产品例子，主帖是扩展机制讨论。不能把“游戏案例”理解为机制只有游戏用途。

[官方 Mods 说明](https://github.com/anthropics/claude-code/tree/31a3b00bef145a0393d9dbf840a98674fec07712/mods)将使用 Function Hooks 的 Claude Code 插件称为 Mod；[接口定义](https://github.com/anthropics/claude-code/blob/31a3b00bef145a0393d9dbf840a98674fec07712/mods/types/claude-code.d.ts)包含运行与界面相关入口。早期扩展接口仍会变化，不能直接把示例当作所有版本通用配置。

## 2. 插件与 Hook 的关系

| 概念 | 作用 | 产品设计时对应的问题 |
| --- | --- | --- |
| Plugin | 安装、配置、分发一组功能 | 用户如何获得和管理功能 |
| Hook | 在开放事件处观察、检查或处理行为 | 在什么时候接入 |
| Function Hooks / Mod | 当前讨论中的函数式扩展方式及插件形态 | 如何接入相关运行和界面能力 |
| Skill | 组织指令、知识和工作方法 | 希望代理按什么流程工作 |
| MCP / 工具接口 | 接入外部资料与动作 | 代理能读什么、做什么 |
| 独立应用 / IDE 扩展 | 承载界面及连接逻辑 | 用户在哪里看到和操作 |

插件可以包含 Hook，但二者不是同义词。Hook 也不是所有产品的唯一基础。VS Code 插件和 Claude Code 插件属于不同宿主，安装位置和能力边界不同。扩展工作流程和工具连接不等于自动改变模型参数或推理能力。

传统 Hooks 的配置和事件见[官方文档](https://code.claude.com/docs/en/hooks)。不要把传统事件名与 Function Hooks 中的点分事件名不加转换地混用。

## 3. 如何观察多代理运行

一个可信的可视化产品可以拆成三层：执行器产生真实运行事实，观察层归一化事件，展示层把状态变成卡片、角色或动画。用户操作若要真正改变执行，还需要独立的控制接口和回执。

| 方法 | 适合的条件 | 主要局限 |
| --- | --- | --- |
| Hooks | 给已有宿主增加事件采集 | 只能看到开放的接入点 |
| 会话日志 | 回看历史、补充实时事件 | 格式、时延、静默状态存在歧义 |
| SDK / API | 自己开发并启动代理应用 | 消息语义和子代理可见性取决于接口 |
| 工作流状态 | 有节点依赖、人工审核、恢复要求 | 检查点不能自动撤销外部副作用 |
| Trace / Span | 排查跨服务耗时和调用关系 | 需要埋点，追踪本身不负责调度 |
| 进程与心跳 | 检测退出、崩溃和失联 | 进程活着不代表工作有进展 |

参考：[Agent SDK](https://code.claude.com/docs/en/agent-sdk/streaming-output)、[LangGraph streaming](https://docs.langchain.com/oss/python/langgraph/streaming)、[检查点](https://docs.langchain.com/oss/python/langgraph/persistence)、[OpenTelemetry traces](https://opentelemetry.io/docs/concepts/signals/traces/)。这些方法可以组合，并无“一般都必须用 Hook”的统一结论。WebSocket/SSE 是传递事件的通道，不自动产生监控事实。

后续实现应至少保留会话/任务/代理身份、事件时间、来源、工具、状态依据和产物位置；处理重复、乱序、重连和未知状态。状态可分为执行中、等待输入、本轮结束、失败、失联。真实百分比需要明确工作量或已知检查项，不能从角色动画或事件数量推断。

## 4. 游戏、桌面与可视化的三种用途

1. 等待时娱乐：用户玩游戏，任务结束事件触发暂停或提醒。游戏胜负与工作质量无关。
2. 运行可视化：人物读书、打字、举手等动作映射真实状态。它帮助发现等待与异常，不能替代验收。
3. 游戏式控制：用户派发、取消、重试任务，界面调用真实调度接口并等待回执。仅有动画不构成控制能力。

桌面伴侣、浏览器办公室、终端小游戏和 IDE 面板是不同承载界面。桌面常驻窗口还需要宿主窗口与操作系统集成能力；本研究网页没有实现真实桌面悬浮窗。

网页中每项都有用户、问题、工作流程、技术机制、最小版本、产出、限制与成功指标；可筛选后导出。40 个方向为原创产品推演，不是已安装插件列表。

| 类别 | 四个方向 |
| --- | --- |
| 需求与输入 | 需求预检、任务模板、变更范围确认、上下文装配预览 |
| 知识与上下文 | 项目决策记忆、会话交接、上下文预算、资料溯源 |
| 执行与质量 | 防跑偏监督、交付验收、测试选择、快照与恢复 |

| 观察与成本 | 多代理总览、运行时间线、预算耗时、调用链诊断 |
| 协作与调度 | 角色分工、任务队列、人工接力、多方案比较 |
| 界面与陪伴 | 像素办公室、桌面伴侣、等待小游戏、游戏式控制台 |
| 研究与内容 | 开源研究、内容交付、实验复现、学习解释 |
| 业务与集成 | 工单交付、设计实现检查、数据分析、运维诊断 |

## 6. 真实案例与借鉴范围

- [Pixel Agents](https://github.com/pixel-agents-hq/pixel-agents)：原 `pablodelucca/pixel-agents`，办公室角色表达代理状态，当前资料包含 VS Code 和独立浏览器形态。传统 Hooks 为主、日志补充。与用户回忆较吻合，但无法确认就是记忆中的唯一仓库。
- [Claude Office](https://github.com/paulrobello/claude-office)：主代理/子代理角色、工位与可视化隐喻，参考其事件采集和场景表达。
- [cc-arcade](https://github.com/sezaakgun/cc-arcade)：最初评论对应项目，参考 Function Hooks、界面渲染与结束事件的联动。游戏本地执行不消耗模型 token，不表示代理任务本身免费。
- [Office for Claude Agents](https://github.com/percheniy/office-for-claude-agents)：额外办公室方案；部分新增内容有非商业许可，不能把整个衍生项目视为统一 MIT。
- 原帖中的[命令按钮](https://github.com/anthropics/claude-code/issues/91870#issuecomment-5714446174)和[防跑偏监督](https://github.com/anthropics/claude-code/issues/91870#issuecomment-5721846986)为开发者报告，未本地复现。

## 7. 对我们的实际意义

核心价值是获得一条产品开发路径：围绕 Agent 工作过程中真实存在的需求，用插件组织功能，通过 Hook 或其他接口接入过程，再实现自己的界面、存储、调度与业务逻辑。可以做监控台、像素办公室、桌面伴侣、等待小游戏、效率与安全助手、业务工作台等。

结合本仓库，项目研究助手是一个可选起点：版本确认、许可证核对、运行、截图、结论与索引维护可以组成带进度和证据的工作台。这里并不是研究 Agent 的通用能力分类，也不要求每个产品都调用模型作推理。

开发路线：选择明确需求 → 确认可用事件与动作 → 开发最小产品 → 用真实任务验证 → 迭代和分发。观察状态和控制任务须分别接入；实际产品价值需要用户和运行数据验证。
