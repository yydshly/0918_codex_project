我们的核心理解

这是围绕 Agent 工作过程开发产品的扩展方式。插件组织功能，Hook 接入运行环节。
对我们的意义：借鉴这些机制与案例，开发自己的功能、界面和工作流程；40 个方向是产品设想，并非库中已提供的成品。

与 Skill / MCP 如何配合？Skill 提供工作方法与约定，MCP 连接可调用的工具，Hook 连接执行环节，插件把相关内容组织成可复用的包。

也可以是独立应用。浏览器看板、VS Code 扩展、桌面宠物都能承载体验。VS Code 插件和 Claude Mod 属于不同宿主，不能混为一谈。

这里研究的是运行扩展，不是 Agent 的能力分类。接入点包括输入提交、工具调用前后、权限与等待、会话状态、输出交付和界面通知；只在宿主实际开放的接口上接入。

扩展点提供机会，产品需要继续开发。游戏可以只接收结束通知；监控台需要状态采集与存储；任务控制台还需要调度接口与执行回执。理解、规划等模型能力是另一个维度。

深入一点：Function Hooks 的“中间件”是什么意思？

一个事件可以经过多个处理函数。每个函数拿到事件数据 e、能力接口 $ 和继续执行的 next。它可以检查后继续、改写输入、等待下一层结果再处理，或直接结束这条处理链。

这使一个“工具调用”介入点能够同时表达执行前、执行后和替代行为。插件顺序会影响结果；宿主通过统一能力接口提供访问与约束。具体开放能力、错误和超时行为需要按版本验证。

02 / FROM EVENTS TO EXPERIENCE

多代理怎么运行，又怎么被看见？

运行、观察与展示，是三个独立层次。

执行层

谁来做、何时做

SDK、进程、任务队列或工作流负责启动、分工、交接与取消。

观察层

发生了什么

通过事件、日志、状态和心跳，整理执行、等待、失败与结束。

体验层

怎样让人看懂

同一份状态既能做成表格、时间线，也能驱动角色、桌宠和游戏。

传输方式不等于数据来源。 WebSocket、SSE、轮询把状态送到页面；Hooks、日志、SDK 等提供状态依据。多种来源可以组合，而非六选一。

在线 ≠ 有进展进程还活着，可能正在等待外部结果。

本轮结束 ≠ 目标成功是否交付，需要独立验收证据。

动画 ≠ 完成百分比没有明确阶段，不能虚构进度。

    06 / BUILD PRODUCTS OF OUR OWN

    对我们的意义：可以基于这些开发产品。

    借鉴扩展机制和真实案例，选择自己的用户需求，做出可使用、可定制的产品。

    选择场景

    找到产品需求

    运行监控、桌面陪伴、等待娱乐、效率提升、安全检查或业务流程。

    →
    组合实现

    做出自己的体验

    插件组织功能，Hook 接入过程，按需连接工具、存储、界面与调度。

    →
    交付产品

    验证真实价值

    形成插件、网页、IDE 扩展或桌面应用，验证需求后持续迭代。

    1. 01

      选择一个明确需求

      例如“任务等我确认时及时提醒”，或“用像素办公室同时观察多个任务”。先确认目标用户与使用场景。

    2. 02

      确认开放接口

      列出需要的事件、状态和动作，核对宿主版本。能显示状态不代表能够取消或派发任务。

    3. 03

      开发最小可用产品

      接入一个真实来源，完成界面与关键业务逻辑。桌面伴侣需要窗口能力，控制台需要调度回执。

    4. 04

      验证后迭代与分发

      通过真实任务验证稳定性和使用价值，再完善配置、安装、兼容性与产品分发。

    结合我们已有工作，可以先试“项目研究助手＋状态可视化＋交付验收”。

    把仓库阅读、运行验证、证据收集和报告整理做成一个工作台。这是可选的起步场景；监控、陪伴、游戏和其他业务产品同样可以探索，尚未做用户或市场验证。
