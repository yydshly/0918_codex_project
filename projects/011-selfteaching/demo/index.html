先建立一个认识

这是一本以编程为案例的自学书。它既讲学习方法，也提供可运行的 Notebook 和 Python 基础；它能为继续学习搭桥，读完之后仍需要练习、作品与反馈。原书的定位 ↗

这个库是什么 / 对我有什么用

一套学习方法，一门 Python 实践课。

用编程的可观察反馈，把阅读、练习和独立完成作品连接起来。适合新人建立入口，也适合进入陌生领域时查漏补缺。

能力与方向
独立阅读与持续学习；Python 基础与进阶；技术文档检索、问题拆解和沟通协作。
方法与技巧
重读与整理概念、刻意练习、以用带练、拆小任务、测试反馈、注意力管理；用成果检验理解。
提供哪些资料
Markdown 正文、可运行的 Jupyter Notebook、代码示例、编辑器 / Git / JupyterLab 工具附录，以及官方文档和延伸阅读入口。
对我的意义
研究新项目时读说明、做最小验证、记录结论；学习工具时带着任务补知识；与 AI 协作时自己判断和复核。已有编程基础可按需查阅。

使用判断：主要价值在学习方法与研究习惯；Python 部分可作入门复习。它不直接增加 AI 工具的执行能力，也不覆盖完整职业开发训练。AI 协作应用是本项目延伸建议。

A / 自学方法 把学习变成可持续的行动 ＋

独立阅读与知识整理

允许第一遍留下疑问，再通过重读、列表和关系图连接概念。用自己的例子讲清楚，避免把浏览当成理解。

可观察的结果

能根据资料完成一个操作，并解释关键概念；能找到自己还不懂的地方。

对应阅读：过早引用 ↗

针对性练习与反馈

从自己的错误中选出薄弱点，用变化输入练习。记录原来哪里不会、现在有什么证据。

可观察的结果

示例换了数据或条件，仍能独立完成；能解释出错原因。

对应阅读：刻意练习 ↗

拆解、耐心与注意力

把难题拆成可操作的小单元，把概念层与实现层分开。每次围绕一个问题推进，旁支兴趣另行记录。

可观察的结果

能把“大项目”缩小为今天可完成的一步，并完成它。

对应阅读：拆解 ↗ · 注意力 ↗
B / Python 实践 从看懂代码到交付小工具 ＋

描述数据与处理步骤

用值、表达式、分支和循环描述任务；根据文本、顺序、去重或映射需要选择结构，再连接文件输入输出。

可观察的结果

能把一份文本清理、筛选、计数，再写入一个新文件。

对应阅读：基础入口 ↗ · 文件 ↗

组织、说明与验证程序

从一个小函数出发，明确参数与返回值；添加说明、模块和入口，用测试检查预期与实际是否一致。

可观察的结果

模块可被复用，别人照说明能运行，边界输入有检查。

对应阅读：从函数开始 ↗ · 测试 ↗

选择更合适的抽象

类用于组织状态与行为，生成器用于逐项产生数据，装饰器用于包装函数，正则用于规则化文本匹配。

可观察的结果

知道语法，也能说清为什么这里适合用它、何时不用它。

对应阅读：类 ↗ · 函数工具 ↗
C / 资料与协作 让学习不止于一本书 ＋

查证与阅读技术文档

区分教程、API 参考和语法描述。搜索提供线索，回到对应版本的文档，再用最小例子检验理解。

可观察的结果

面对陌生函数，能找出参数、返回值与使用条件。

对应阅读：官方教程 ↗ · BNF / EBNF ↗

留下证据，获得反馈

通过版本记录、完整的小作品和清楚的说明，与他人讨论实际问题。可以先在本地保留证据，再按需分享。

可观察的结果

能说明自己改了什么、为什么改，以及结果是否变好。

对应阅读：学习证据 ↗ · 社交 ↗

表达与迁移

围绕接收者组织内容，把问题讲明白。对没有现成教程的问题，逐步提出与检验假设。

可观察的结果

别人能理解你的成果；你能为下一个陌生问题设计起步实验。

对应阅读：沟通 ↗ · 终点 ↗
适合怎样使用

初学者用它建立入口；会写一点代码的人用它补齐练习方法；研究者用它反思阅读、验证和输出。它不提供完整的 Web、数据科学或 AI 工程训练，不能单靠阅读时长判断能力，也不承诺就业结果。

PROJECT 01入门

做一个文本整理器

把混乱的词条清理成一份去重后的清单，再输出到新文件。

字符串集合文件
查看任务与验收 ＋

输入与目标

输入：" Python  \npython\n Git \n\n"
输出："python\ngit\n"

约定：去首尾空白、统一小写、忽略空行、按首次出现顺序去重。需要同时利用顺序记录与去重结构。

  1. 先手工写出样例的预期结果。
  2. 把纯文本清理写成函数，再连接文件读写。

完成的证据

  • 普通输入、空文件、重复词条三个检查通过。
  • 更换输入后仍可运行，原始文件保留。
  • 能解释为什么单独使用集合不足以表达这份顺序约定。

PROJECT 02进阶

做一个日志摘要器

函数正则测试
查看任务与验收 ＋

输入与目标

预期：INFO = 2，ERROR = 1

约定：只接受 INFO、WARN、ERROR 三种等级；格式错误的行单独计数，不静默丢弃。

06 / WHEN YOU GET STUCK

卡住时，换一个可操作的问题。

先识别卡在哪里，再决定怎么继续。
以下行动建议依据原书方法独立编写。

看了几页，陌生名词越来越多 ＋

先把名词记到问题清单，继续读到一个完整小节的结尾。第二遍补齐影响理解的概念，再自己画关系图。必须立即操作时，先弄清输入与输出。

回到“过早引用” →
跟着例子能做，合上书就不会 ＋

缩小到一个函数：先写自然语言步骤和输入输出，再独立实现。记录具体缺的是语法、概念还是拆解能力；换一组数据再做。

回到“为什么从函数开始” →
程序能运行，但结果不对 ＋

选一个能手工算清的小样本，列出预期与实际。从最早出现差异的步骤检查，再补一个能复现问题的测试。能启动不等于逻辑正确。

回到“测试驱动的开发” →
一开始就想做大项目，迟迟没有成果 ＋

把需求拆成读取、处理、输出等独立步骤；先完成一个最小输入到输出的全过程。等这一步可重复运行后，再扩大范围。

回到“拆解” →
装工具、换主题、找课程花掉了所有时间 ＋

写下今天要解决的唯一问题；工具只有阻碍这个问题时才调整。临时发现的资源放入待办，当前任务做完再看。

回到“避免注意力漂移” →
搜索没有答案，提问也没人回应 ＋

整理目标、软件版本、最小输入、完整错误、预期与实际，以及已经试过的方法。用这份材料重新检索，再到合适的社区提一个具体问题。

回到“这是自学者的黄金时代” →
旧书里的安装步骤和我的电脑对不上 ＋

先区分学习目标与某一版本的界面操作。原书保留历史情境；安装、插件与配置项以当前官方文档为准。只读正文时可先使用 Markdown。
